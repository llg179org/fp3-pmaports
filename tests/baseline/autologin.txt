# Budget for the boot-to-session time, in seconds of MONOTONIC time since boot.
#
# AUTOLOGIN_MAX does two jobs, and the second is the important one. It is a
# regression gate on how long the boot takes to reach a usable session; and it
# is the only thing separating an autologin from a human who happened to unlock
# the phone before the check ran. This test cannot see a hand on the device -
# it can only see that the session existed seconds, not minutes, into the boot.
#
# So keep it tight enough that a person could not have done it. Both sides were
# measured on 7.1.3 on 2026-08-16, on the same phone within the hour:
#
#   autologin ([initial_session] on)   session 16.9s, phosh 24.1s after boot
#   human unlock                       session 81.6s, phosh 89.0s after boot
#
# A factor of 4.8 between them, so the threshold is not delicate. 40s sits in
# the gap with room on both sides: it would take a boot 2.4x slower to trip it,
# and a person 2x faster to sneak under it.
AUTOLOGIN_MAX=40.0
